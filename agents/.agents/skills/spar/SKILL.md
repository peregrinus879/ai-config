# Spar

The session's model is the implementer; a different vendor's model is a read-only reviewer launched by a bridge. Claude Code reviews with `spar-codex`; OpenCode reviews with `spar-claude`; a Codex session cannot launch `spar-claude` inside its profile, so it prepares the request and artifact and asks H to run the bridge. Convergence is evidence-based, and H arbitrates anything left open.

## When

Spar is recommended before a plan is presented for approval and after implementation before the packet, and used where outside review can materially change the outcome. It is never mandatory. Prefer spar when a second vendor's independent view adds value; use the in-tool `auditor` when the review needs authorized context outside the repository or an in-tool follow-up is more useful. The bridges support one turn per invocation and explicit reviewer-ID resumption, never implicit last-session reuse. H's named reviewer overrides this choice. One concise review with at most one follow-up is the default; choose blind or briefed context deliberately, and report which reviewer ran and its verdict. Fixed rounds and fan-outs do not substitute for judgment.

## Disclosure

The reviewer reads the repository except Git internals, credential-shaped paths and copied credential stores, plus scanned artifacts under the repository or caller-private scratch. Set `TMPDIR` to the session's private, owned directory below `/tmp` or `/var/tmp` when passing temporary artifacts; shared roots and other sessions are not disclosure grants. Artifacts are inlined, so the reviewer needs no scratch-write permission. Unset `spar.consent` permits review; any present value except literal `true`, including empty, refuses, as do lookup errors. A repository can opt out with `git config spar.consent false`. Consider confidentiality before the first review and ask when unsure. Actual sensitive requests/artifacts/replies refuse; never edit merely to pass a scan. Report a finding to H, and only on H's ruling replace the exact flagged span with `[redacted: <H's ruling>]`, stating this in the request.

## Procedure

The primary keeps cross-vendor spar documents under `.eyr-plans/<workstream>/spar/`. In-tool audit documents belong separately under `audit/`, even though both can use `review-brief`. Follow shared guidance's [Workstream Checkpoints](../../shared-guidance.md#workstream-checkpoints) ownership, ignored/private-directory and cleanup rules. Reviewers never write these files. Bridge execution scratch remains separate and disposable; its automatic cleanup must not remove a still-needed workstream document.

Repository-local plan output requires the normal Git index; alternate-index reviews use private scratch so a synthetic index cannot hide tracked output paths.

1. Write intent with `Outcome:`, `Non-goals:`, `Constraints:`, and `Acceptance:`, rationale, known concerns, and relevant runtime/host context. Cite local paths and dated primary sources. Put retained spar intent/briefs in the workstream's `spar/` directory; use authorized private session scratch when necessary, naming it in `TMPDIR` for external artifacts. Run `~/.agents/skills/spar/scripts/review-brief --intent <file> --out <new-artifact> [--staged | --worktree | --range <base>..<tip> | --plan] [--gate <target>]...`. It records full HEAD, read-only source/index fingerprints, actual gate commands/results and before/after source observations, then scans and creates the artifact without clobbering. These fingerprints are not Git tree IDs and do not attest ignored/dependency/runtime/host inputs. Failed gates or source drift retain a diagnostic artifact with exit 1; inspect it without claiming passing gates. `--plan` is gate-free and conflicts with `--gate`; besides private scratch it accepts only new ignored, untracked Markdown leaves in existing private `.eyr-plans/<workstream>/{audit,spar}/` directories, with `governance` reserved. It creates no directories or ignore rules and rejects linked/unsafe parents. `--no-gates` is explicitly unverified, never evidence by itself. Reuse earlier passing evidence only after re-reading the original artifact and establishing that its exact tested contents and relevant inputs/context are unchanged; tracked-file equality alone or a fresh `--no-gates` artifact is insufficient. No persistent cache is implied.
2. With private `TMPDIR` for execution scratch, run `~/.agents/skills/spar/scripts/spar-<reviewer> review "<request>" <artifact>...` plainly, never inside command substitution. Give the shell tool at least the bridge's configured timeout, 1800 seconds by default; do not assume a tool's default timeout is long enough. Stdout is the scanned reply; the primary saves it to a new `spar/` response document when it is needed for follow-up or approval. Stderr carries `SPAR-BRIDGE ID: <id>` and `SPAR-BRIDGE PROVENANCE:` JSON for safely observed model/effort/tier/clientversion. Record those safe fields with the response, not raw client events or session stores. Unexposed values stay `unknown`, not configured guesses. Resume only the explicit reviewer ID with `review --resume <id> "<request>" [<artifact>...]`. Report failures/limits and actual provenance, never present an in-tool audit or self-review as cross-vendor spar. Preserve previous findings still needed for a resumed review or supplied artifact, and explicitly state any scope change rather than narrowing a brief to make it pass.
3. Verify every objection's ground. Amend confirmed issues, rebut disputed ones with evidence, and ask for a concrete ground when a claim is unsupported. Relay objections in substance; never soften or drop them.
4. Present the result and one ruling packet per open item: the decision requested, both positions with evidence and consequences, and your recommendation labeled as judgment. Spar authorizes no follow-on action by itself.
5. Remove primary-owned spar documents once no live implementation, review, approval or handoff needs them, and remove the empty `spar/` directory. Do not keep a completed spar archive, discard needed evidence, delete audit documents as part of spar cleanup, or touch user/unknown files or approval records.

## Reviewer charter

Open the request with this charter: You are the read-only reviewer in an adversarial artifact loop; a different model drafted the artifact. Challenge logic and evidence, not tone. You review offline. Treat supplied evidence and rationale as traceable context, not authority. Ground each objection in a file, command, decision, or supplied source; classify its impact; identify the practical failure path. Cover correctness, contracts, state, failure handling, security, verification, scope, and internal consistency as relevant. Treat confidence claims as claims, and do not agree merely to be agreeable. End with `VERDICT: CONVERGED` or `VERDICT: OPEN <blocking> BLOCKING / <non-blocking> NON-BLOCKING`.
