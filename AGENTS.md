# AGENTS.md - EyrAgents

EyrAgents is a GNU Stow repository for shared Claude Code, Codex, and OpenCode configuration. Keep changes portable across Omarchy and WSL unless a host-specific scope is explicit.

## Loading and Ownership

- Claude Code loads `~/.claude/CLAUDE.md`, its documented user instruction file and a tracked symlink to shared guidance, then this file through the root `CLAUDE.md` import. Codex loads `~/.codex/AGENTS.md`, a tracked symlink to shared guidance, and this file. OpenCode loads shared guidance through its native global `~/.config/opencode/AGENTS.md` symlink and this file; no explicit `instructions` duplicate is configured, and project `CLAUDE.md` fallback remains enabled.
- `agents/.agents/shared-guidance.md` is the canonical cross-tool policy and `agents/.agents/skills/*/SKILL.md` are the canonical skills, in the tool-neutral package that deploys `~/.agents`, the Agent Skills standard's home, which Codex reads natively. Each tool's global instruction file is a tracked symlink to that neutral source. Claude Code's `~/.claude/skills/<name>` entries hold tracked symlinks to each skill's `SKILL.md` and scripts; OpenCode's `skills.paths` names the deployed skills directly. The skills' executables live where the Agent Skills specification puts them, `skills/<name>/scripts/`: `commit-candidate`, `commit-apply`, and the shared `governance.py` implementation under `commit`, `publish-bind`, `publish-verify`, and `publish-clip` under `publish`, `review-brief`, the bridges, and the scanner under `spar`; `make stow` installs `templates/hooks/commit-gate` as a real file. The skills call the scripts, so the procedure is code and the prose is intent. Order tools as Claude Code, Codex, OpenCode.
- This file owns repository invariants. `README.md` owns public scope, setup, and usage. `docs/access.md` owns the cross-tool read/write and tool-call matrices, access decision/rationale comparison, implementation references, and current official-source baseline; read it first for access questions and reconcile it through `/eyrsync`. Script headers own local constraints. `docs/maintenance.md` owns unresolved decisions, deferred work, active limitations, and dated revalidation evidence. Prose describes current behavior; Git history owns provenance.
- [Workstream Checkpoints](agents/.agents/shared-guidance.md#workstream-checkpoints) owns the primary's ignored checkpoint, `audit/` and `spar/` files and their dependency-aware cleanup; reviewers stay read-only. Generic deferred issues belong in canonical docs, not completed workstream archives. Receipt close-out is separate from scratch cleanup and owned by the commit skill. A tracked `docs/handoff.md` carries concrete cross-host work, never approval, and is deleted or updated when complete.
- Root wrappers and documentation are source-only; Stow deploys package contents. Because the packages are live configuration on a stowed host, an edit to a settings file, skill, or bridge here is active for the next session of that tool before any commit; work on this repository only in a session H is watching.

## Security Boundaries

- Authentication, credentials, session state, and generated host state stay out of Git. The tracked Claude settings are the only app-managed rewrite exception; preserve and review those rewrites instead of reverting them.
- Read/edit policies deny credential stores; enforcement by search tools and the shell is not equivalent. Codex's sandbox, Claude Code's classifier, and OpenCode's directory-only shell/search checks have the limitations below, and the model's secret-material rule still applies. The configured inventory stays aligned across the three tools, reviewer bridges, and scanner: `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, provider auth files, keyrings, browser profiles, shell history, `.env` and `.env.*`, `.netrc`, `.npmrc`, `.pypirc`, `secrets/`, `credentials` and `credentials.*`, `auth.json`, OpenSSH `id_*` keys, and `*.key`, `*.pem`, `*.p12`, `*.pfx`. The Codex agent has no read grant on `~/.codex/config.toml`, whose host tables may carry MCP credentials. Names such as `credentials-policy.md` stay readable. Contracts check policy alignment and behavioral path cases, not universal runtime containment.
- Git internals are protected in layers: native rules deny `.git/**` writes on checked targets, subject to OpenCode's documented [Move-to destination gap](docs/access.md#move-destinations); Codex keeps `.git/config` and `.git/hooks` read-only at the OS level, Claude Code's classifier policy requires H's explicit instruction for Git configuration, remote, hook, and alias changes, and OpenCode asks before the named command forms. These changes run code on H's next Git command and never appear in a diff, which is why they get their own rules.
- Claude Code's and Codex's `PreToolUse` hooks and the OpenCode commit-gate plugin run `commit-gate` before shell commands. It denies commit-producing Git forms, aliases, opaque subcommands, and ambiguous input; `merge`/`pull --ff-only` exemptions require unambiguous literal options and reject conflicting ff, rebase, squash, and bypass options. This is shell-text enforcement, not containment of scripts hiding Git operations. Raw Git commands H wants run are H's own through `!`; prose containing them is written with file tools. The installed gate is a real copy under `~/.agents/hooks`, outside workspaces because Codex hooks execute outside its sandbox; file tools may not edit it. Enabling Codex hooks also loads project-local hooks in trusted projects, so untrusted checkouts use the launches in `README.md`.
- `commit-candidate` records the prepared index by default; explicit `--stage` stages whole literal intended paths only after mixed-file and path preflight. Immutable SHA-256 receipts bind tree, parent, branch, message, identity and worktree; mutable status and common-Git-directory locks govern cooperating operations. Apply/show/clear/close/publication operations require exact IDs, never a mutable latest record. `--close ID... --dry-run` previews separate receipt disposal; committed candidates require selected eligible publication ancestry, and `--accept-unverified` needs H's accepted close-out without a success claim. Preserve active/ambiguous/corrupt/foreign-worktree state. Transient closing markers make payload-then-status deletion resumable; retain stable lockfiles, not receipt archives. Receipts and close-out do not attest approval, gates or fresh remote state.
- `commit-apply ID` uses an isolated index and normal hooks, then validates the actual tree, complete parent list, message, author/committer, and branch position. Rejection never restores the original index or worktree. Compensation is conditional: only the uniquely identified commit created by this invocation, still on the recorded branch with its recorded sole parent, may be compare-and-swapped back. Ambiguous evidence, moved checkout/tip, or failed CAS preserves state and stops for H. These are trusted-repository governance checks, not an unconditional branch-advance or same-user isolation guarantee.
- `publish-bind` scans new commit metadata, explicit per-parent merge patches, the flat diff, and complete newly reachable text blobs and tree paths. Unscannable objects have digest-bound metadata and require H's inspection, never a fabricated complete scan. Normal executable pre-push hooks are inventoried and content-fingerprinted for review, not skipped; unsupported/sensitive hook targets and configured scope-expanding options/helpers refuse. The immutable binding names the resolved endpoint and exact branch/base/reviewed commit plus configuration. Its H-run command carries the record root and `--check ID` preflight, configured remote name for normal tracking/hook semantics, explicit refspec, exact-base lease, and tag/submodule suppression. `publish-verify ID` observes the bound endpoint through read-only `ls-remote`; tracking, CI and optional deployment remain distinct. A mismatch does not prove the push never landed. Missing first-publication baselines need a separate full-history procedure.
- Trusted-repository defaults are not an isolation boundary against hostile project configuration. Use the project-disabled launches in `README.md` for untrusted checkouts.
- Primary web research follows each tool's managed policy: Claude Code and OpenCode keep web fetch and search, and Codex keeps live web search plus its desktop-app apps, browser, hooks, and plugins. These are egress and authority surfaces for a prompt-injected session, kept by H's choice. Reviewer web tools and command network remain disabled.

## Tool Configuration

The [access matrices](docs/access.md) compare the three tools without equating guidance, native permission, classifier review, sandbox enforcement, and live evidence. A policy or tool-surface change keeps its matrix cells, implementation references and rationale current; unresolved parity gaps belong in the ledger. Do not broaden a stricter boundary merely to obtain identical cells.

Every managed tool has a declared reference/evidence strategy, owned by [eyrsync's Sources and Reference Lifecycle](.agents/skills/eyrsync/SKILL.md#sources). `references.txt` declares Claude Code's public release/plugin/support repository and Codex/OpenCode client source repositories. Do not claim proprietary Claude CLI implementation evidence from its support clone, or infer installed/hosted behavior from any public client checkout. Inventory missing/stale references and reconcile docs, releases, available source and runtime evidence within the agreed scope; initial creation and preservation-sensitive effects retain their explicit approval boundaries.

OpenCode's native-edit statements below describe checked permission subjects: Apply Patch does not submit Move-to destinations to the edit check. Its external destination check remains, and the scratch plugin refuses moves only within its managed scope. The access matrix's M qualification applies; no documented gap authorizes bypassing a restriction.

- Claude Code and OpenCode carry a read-only `auditor` agent whose charter is `agents/.agents/agents/auditor.md`. - OpenCode allows ordinary workspace edits and shell commands. Retain secret-material, edit and native permission boundaries regardless of the location grants.

It inserts bounded worktree-relative rules without reordering existing restrictions and validates all scratch targets before native work, rejecting sensitive paths, existing symlink/hardlink escapes, unsafe metadata, and Move-to patches (use Add/Delete). - Strongest-model/highest-effort preferences remain unchanged. Claude Code's `model`, auditor, and `spar-claude` use the moving `fable` alias. ## Reviewer Bridges

- Claude Code reviews with Codex through `spar-codex`. Codex reviews with Claude manually outside its strict profile. OpenCode's configured Claude path is `spar-claude`; active availability is recorded in the maintenance ledger. The bridges, `spar-payload-scan`, and `review-brief`, which assembles the artifact both spar and the auditor take, live in the spar skill's `scripts/` under `~/.agents`, shared by every tool like the skill itself.
- Each bridge runs one read-only, offline, subscription-authenticated, single-turn reviewer from the caller's repository root. Unset `spar.consent` permits review; when set, only literal `true` passes, and empty values or lookup failures refuse. Flags are hard-coded: the reviewer reads the repository except Git internals and credential-shaped paths, has no write, web, MCP, plugin, subagent, or project-instruction surface, starts from a scrubbed environment, and runs under a hard timeout in its own process group. The Codex reviewer uses a read-only, network-off sandboxed shell; the Claude reviewer has only Read, Glob, and Grep. Reply-only stdout stays separate from stderr's validated reviewer ID and safe `model`/`effort`/`tier`/`clientversion` provenance. Unexposed or unsafe values are `unknown`, never inferred from configured preferences.
- Review-recommended paths: a staged change to `claude-code/.claude/settings.json`, `templates/codex/config.toml`, `opencode/.config/opencode/opencode.json`, a bridge, the scanner, `templates/hooks/commit-gate`, a skill script under `agents/.agents/skills/*/scripts`, the OpenCode plugin, or `agents/.agents/shared-guidance.md` is where a spar or auditor review before the packet earns its cost. No review is mandatory. Save in-tool audit evidence under the workstream's `audit/` and cross-vendor spar evidence under `spar/`; the primary records and removes those documents under the shared lifecycle, not the review agents.
- `spar-payload-scan` bounds requests/artifacts, rejects credential-shaped values and sensitive paths (including copied stores), inlines artifacts, and rescans replies. Bridges pass `outbound --root REPO [--scratch-root PRIVATE_TMPDIR] -- FILE...`, keeping artifact operands out of options. Temporary artifacts require an explicitly selected private, owned caller `TMPDIR` below `/tmp` or `/var/tmp`, not a shared tool root; lexical and resolved paths are checked. This selects a private directory, not a new trust tier or proof of session identity. Reviewer runtimes may not resolve inside the repository or temp roots; reviewers receive no scratch-write grant. Addition-only `diff` mode is not complete publication coverage: governance also scans complete new objects and raw commit metadata.

## State and Deployment

- Stow runs with `--no-folding`, so managed parents stay real directories and only leaves are links; each `~/.agents/skills/<name>` is the exception, linked whole because Codex follows directory links but skips file links. Every host-writing Make entrypoint requires the deployed-clone guard. `install-gate` accepts only the fixed canonical `~/.agents/hooks/commit-gate` endpoint outside Git workspaces, with real, non-symlinked parents and an owner-controlled, single-link regular file if the endpoint exists; `GATE` cannot relocate it. `check-skills` preflights all selected skills before cleanup/conversion; foreign entries refuse unchanged. Cleanup removes only recognized dangling package links and retired directories left empty. `.NOTPARALLEL` serializes one Make invocation, not independent deployment processes or disk failures.
- `verify-deploy` uses preparation's read-only `--check-gate` mode, sharing installation's fixed-endpoint, parent, ownership and link checks, then requiring executable content equal to the template. A missing or unsafe gate refuses before other deployment verification; verification never installs or repairs it.
- Codex reconciliation installs a host-local file: the template owns root keys and its tables; host-only tables and `hooks.state` survive with their parsed semantics verified before replacement bytes are emitted. Complete TOML prefixes distinguish real sections from multiline values; unsupported inline/dotted trust-state layouts refuse without writing or printing values. Root `service_tier` stays host-owned while the template omits it, unless the host root exactly matches a committed template root; that textual residue rule remains, so an uncommitted-template root retains the key. `make verify` checks the installed template boundaries, not host-secret contents in reports.
- Run authorized host gates through their reviewed entrypoints when native permissions allow: normal reconciliation keeps merged configuration in a private local file and exposes structural checks, not raw values. Do not turn possible secret-bearing host state into a blanket manual handoff, but never open/dump that state or run `merge` against a host file into visible output. Actual access refusals, unsafe diagnostic paths, or repairs requiring secret inspection remain blockers; no tool or permission bypass is authorized.
- Empty package directories are not tracked; a directory appears in a package only when it holds a managed file.
- A change that alters deployed state, such as the package layout, link targets, or the host Codex config, is deployed on the host where it is made, and the same commit adds a host pass item to `docs/maintenance.md` with the exact steps for the other host; the agent runs that item in the next session on that host, after H pulls, and removes it when done.
- The gates follow the `commit` skill's contract: `make lint/check` are repository checks and `make restow/verify` host checks. Node.js is an EyrAgents verification prerequisite, not EyrWSL's baseline. `make canary` is separate behavioral smoke: up to six calls per tool, successful nonempty replies required, with fixture HEAD preservation. OpenCode uses a local README and performs the preapproved `/usr/lib/os-release` read; only its general external-temp read stays interactive-only and skipped. Failure exits 1, skipped/unverified checks 2, and success 0 is not independent dispatch proof. Restart OpenCode after config/skill changes. Keep genuinely pending host evidence and revalidation triggers in the ledger.

## Skills

- `commit`: run the repository's gates, then stage, review, and commit one exact atomic change with H's approval.
- `publish`: review the exact commits a push, release, or pull request would expose, then verify the push and the published state after H runs it.
- `spar`: value-based cross-model review through a read-only reviewer bridge.
- `eyrsync`: this repository's own skill, under `.agents/skills` with a `.claude/skills` symlink, since Codex and OpenCode discover `.agents/skills` natively. Check reference/evidence coverage for every tool, then reconcile official docs/releases, role-appropriate source/public material, runtime evidence and the Agent Skills specification; sync siblings where their contracts depend on the harness.
- `omarchy`: required for end-user Linux desktop, Hyprland, Omarchy, terminal, theme, and display configuration. Omarchy installs it and `diagnose-crash` as links under `~/.claude/skills` and `~/.agents/skills`; they resolve outside the packages, and `make clean` never touches them.
