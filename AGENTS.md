# AGENTS.md - EyrAgents

EyrAgents is a GNU Stow repository for shared Claude Code, Codex, and OpenCode configuration. Keep changes portable across Omarchy and WSL unless a host-specific scope is explicit.

## Loading and Ownership

- Claude Code loads `~/.claude/CLAUDE.md`, its documented user instruction file and a tracked symlink to shared guidance, then this file through the root `CLAUDE.md` import. Codex loads `~/.codex/AGENTS.md`, a tracked symlink to shared guidance, and this file. OpenCode loads shared guidance through its global `instructions` entry and this file.
- `agents/.agents/shared-guidance.md` is the canonical cross-tool policy and `agents/.agents/skills/*/SKILL.md` are the canonical skills, in the tool-neutral package that deploys `~/.agents`, the Agent Skills standard's home, which Codex reads natively. Each tool's own file carries the name that tool documents and points at the source: Claude Code's `~/.claude/CLAUDE.md` is a tracked symlink and its `~/.claude/skills/<name>` entries hold tracked symlinks to each skill's `SKILL.md` and scripts, Codex's `~/.codex/AGENTS.md` is one, and OpenCode's `instructions` entry and `skills.paths` name the deployed guidance and skills directly. The skills' executables live where the Agent Skills specification puts them, `skills/<name>/scripts/`: `commit-candidate`, `commit-apply`, and the shared `governance.py` implementation under `commit`, `publish-bind`, `publish-verify`, and `publish-clip` under `publish`, `review-brief`, the bridges, and the scanner under `spar`; `make stow` installs `templates/hooks/commit-gate` as a real file. The skills call the scripts, so the procedure is code and the prose is intent. Order tools as Claude Code, Codex, OpenCode.
- This file owns repository invariants. `README.md` owns public scope, setup, and usage. Script headers own local constraints. `docs/maintenance.md` owns unresolved decisions, deferred work, active limitations, and dated revalidation evidence. Prose describes current behavior; Git history owns provenance.
- [Workstream Checkpoints](agents/.agents/shared-guidance.md#workstream-checkpoints) in shared guidance owns the recurring local checkpoint workflow. Follow it without a separate skill; the primary owns the gitignored milestone summary, which is neither approval nor cross-machine transport and is retained locally after completion while session scratch is removed.
- Root wrappers and documentation are source-only; Stow deploys package contents. Because the packages are live configuration on a stowed host, an edit to a settings file, skill, or bridge here is active for the next session of that tool before any commit; work on this repository only in a session H is watching.

## Security Boundaries

- Authentication, credentials, session state, and generated host state stay out of Git. The tracked Claude settings are the only app-managed rewrite exception; preserve and review those rewrites instead of reverting them.
- Credential stores are neither readable nor writable through any tool's file tools, and the shell side is sandbox-denied in Codex, except a project `.npmrc` under `~/Projects` as the Tool Configuration section records, classifier-gated in Claude Code, and unguarded in OpenCode. The list stays aligned across Claude Code, Codex, OpenCode, the reviewer bridges, and the payload scanner: `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, provider auth files, the GNOME keyring, browser profiles, shell history, `.env` and `.env.*`, `.netrc`, `.npmrc`, `.pypirc`, `secrets/`, `credentials` and `credentials.*`, `auth.json`, OpenSSH `id_*` keys, and `*.key`, `*.pem`, `*.p12`, `*.pfx`. The Codex agent has no read grant on `~/.codex/config.toml`, whose host tables may carry MCP credentials. Names that merely contain those words, such as `credentials-policy.md`, stay readable. `tests/config-contracts.py` enforces the alignment and the read-write mirror.
- Git internals are protected in layers: file tools cannot write `.git/**` in any tool, Codex keeps `.git/config` and `.git/hooks` read-only at the OS level, Claude Code's classifier clears Git configuration, remote, hook, and alias changes only on H's explicit instruction, and OpenCode asks before the named command forms. These changes run code on H's next Git command and never appear in a diff, which is why they get their own rules.
- Claude Code's and Codex's `PreToolUse` hooks and the OpenCode commit-gate plugin run `commit-gate` before shell commands. It denies commit-producing Git forms, aliases, opaque subcommands, and ambiguous input; `merge`/`pull --ff-only` exemptions require unambiguous literal options and reject conflicting ff, rebase, squash, and bypass options. This is shell-text enforcement, not containment of scripts hiding Git operations. Raw Git commands H wants run are H's own through `!`; prose containing them is written with file tools. The installed gate is a real copy under `~/.agents/hooks`, outside workspaces because Codex hooks execute outside its sandbox; file tools may not edit it. Enabling Codex hooks also loads project-local hooks in trusted projects, so untrusted checkouts use the launches in `README.md`.
- `commit-candidate` records the prepared index by default; explicit `--stage` stages whole literal intended paths only after mixed-file and path preflight. Immutable SHA-256-addressed receipts bind tree, parent, branch, message, identity, and worktree; mutable lifecycle status is separate, with common-Git-directory locking for cooperating operations. Apply, show, clear, publication preflight, and verification require explicit IDs, never a mutable latest record. Receipt creation is not H's approval and does not attest gates or prove that the worktree equals the recorded tree.
- `commit-apply ID` uses an isolated index and normal hooks, then validates the actual tree, complete parent list, message, author/committer, and branch position. Rejection never restores the original index or worktree. Compensation is conditional: only the uniquely identified commit created by this invocation, still on the recorded branch with its recorded sole parent, may be compare-and-swapped back. Ambiguous evidence, moved checkout/tip, or failed CAS preserves state and stops for H. These are trusted-repository governance checks, not an unconditional branch-advance or same-user isolation guarantee.
- `publish-bind` scans new commit metadata, explicit per-parent merge patches, the flat diff, and complete newly reachable text blobs and tree paths. Unscannable objects have digest-bound metadata and require H's inspection, never a fabricated complete scan. Normal executable pre-push hooks are inventoried and content-fingerprinted for review, not skipped; unsupported/sensitive hook targets and configured scope-expanding options/helpers refuse. The immutable binding names the resolved endpoint and exact branch/base/reviewed commit plus configuration. Its H-run command carries the record root and `--check ID` preflight, configured remote name for normal tracking/hook semantics, explicit refspec, exact-base lease, and tag/submodule suppression. `publish-verify ID` observes the bound endpoint through read-only `ls-remote`; tracking, CI and optional deployment remain distinct. A mismatch does not prove the push never landed. Missing first-publication baselines need a separate full-history procedure.
- Trusted-repository defaults are not an isolation boundary against hostile project configuration. Use the project-disabled launches in `README.md` for untrusted checkouts.
- Primary web research follows each tool's managed policy: Claude Code and OpenCode keep web fetch and search, and Codex keeps live web search plus its desktop-app apps, browser, hooks, and plugins. These are egress and authority surfaces for a prompt-injected session, kept by H's choice. Reviewer web tools and command network remain disabled.

## Tool Configuration

- Claude Code runs in auto mode with bypass disabled and no tracked sandbox, with standing read allows on `~/Projects/**`, the temp roots `/tmp/**` and `/var/tmp/**` less OpenCode's session root `/tmp/opencode`, and the system trees `/usr`, `/etc`, `/opt`, `/sys`, and `/var/lib/pacman`, over which the deterministic credential denies still win; deterministic denies cover the named command forms of pushes, `git clean`, `gh` repository mutations, and privilege escalation, plus credential reads and writes by file tools, while alternate spellings, destructive Git operations, Git configuration changes, other `gh` mutations, and persistence surfaces clear through the classifier only on H's explicit instruction. `/doctor` may rewrite `~/.claude.json` and local allowlists; curate durable rules instead of restoring machine state.
- Codex runs the root-denied `trusted-workspace` profile from `templates/codex/config.toml`, installed host-locally by `make stow`, with automatic approval review and command network disabled. The profile grants the mise install directory so the sandbox can execute mise-managed runtimes, `~/Projects` for reading H's repositories and reference clones, the system trees `/usr`, `/etc`, `/opt`, `/sys`, and `/var/lib/pacman` as literal reads, and `/var/tmp` beside the built-in temp grants, with `/tmp/opencode` and `/tmp/claude-1000` denied by literal path; no shape deny can live under a temp root, because the sandbox's glob scan dies on the root-owned entries there, so Codex reads credential-shaped files under the temp roots as it always did and the model refuses them on the guidance. Under `~/Projects`, where the home-wide credential-shape denies keep masking secrets and the shapes those globs cannot cover are denied under `~/Projects` instead, except `.npmrc`, whose glob stalls the sandbox and which therefore stays readable there. Scripted `codex exec` calls use one finite prompt and never `--last`.
- Claude Code and OpenCode carry a read-only `auditor` agent, the spar loop inside the tool, whose charter is the shared `agents/.agents/agents/auditor.md`: Claude Code's agent under `~/.claude/agents` carries a copy of the charter as its body, held equal to the source by the contracts test, with Read, Grep, and Glob only at the highest effort; OpenCode's is the `agent.auditor` entry in `opencode.json`, whose prompt reads the charter file, with edit, bash, web, and subagent launches denied. Agents may only tighten permissions; `tests/config-contracts.py` parses them and enforces the exact tool and deny sets. Codex has no auditor role yet: its `sandbox_mode` restricts only the shell, so a role would also have to disable web search, apps, plugins, MCP servers, and nested agents, and that merged authority must be verified live first; the ledger holds the item.
- OpenCode allows ordinary workspace edits and shell commands, grants native access under `~/Projects/**`, the temp roots `/tmp/**` and `/var/tmp/**` less Claude Code's session root `/tmp/claude-*`, the system trees `/usr`, `/etc`, `/opt`, `/sys`, and `/var/lib/pacman`, and the skill scripts under `~/.agents/skills/**`, which the skills run through its shell, so that reads and those runs never prompt, asks before its file tools edit outside the worktree except in the app temp root, asks for native access elsewhere and before destructive Git operations and Git configuration changes, and denies pushes, `git clean`, repository-host mutations, privilege escalation, remote shells and transfers, and nested agent launches. Permission order is last-match-wins. Read and edit subjects are worktree-relative, so the credential shapes and the credential store copies are denied there by `**/` rules and, since those need a slash, by their bare forms at the worktree root; external subjects are the parent directory plus `/*`, so an external rule that names a file never matches, directory stores under `$HOME` and their copies rely on the external `**/<dir>/**` globs and the ask default, and the shell's file commands and grep raise only that directory subject, which under `~/Projects` the grant allows: the shell sees no shape deny there and no prompt before `rm`, `cp`, `mv`, `chmod`, or `chown` on a sibling repository, where the shared guidance's edit boundary is the only rule. OpenCode has no classifier or sandbox, so its Bash rules are guardrails, not containment.
- Models name a moving target wherever the tool offers one, so a new generation arrives without an edit, and a concrete id only where it does not. Claude Code's `model`, the `auditor` agent, and `spar-claude` name the `fable` alias, which Claude Code resolves to the newest Fable. The Codex template and `spar-codex` pin no model, so Codex's catalog default applies, the first picker-visible model, which is the vendor's strongest today and observable in each session record, as the ledger states; Codex offers the Fast tier as a service tier, never as a picker entry, and it multiplies usage, so the template sets no `service_tier`, `features.fast_mode` keeps the per-session `/fast` toggle available, and `spar-codex` names the standard tier explicitly. OpenCode has no alias: `opencode.json` pins the newest OpenAI model by id and `small_model` the newest mini, both on the standard tier, with the `-fast` variant OpenCode derives from each left as a per-session picker choice; both ids are bumped by hand when `opencode models` lists a newer generation, and the ledger holds the trigger. `tests/config-contracts.py` enforces these shapes, and the effort is `xhigh` in every tool.

## Reviewer Bridges

- Claude Code reviews with Codex through `spar-codex`. Codex reviews with Claude manually outside its strict profile. OpenCode's configured Claude path is `spar-claude`; active availability is recorded in the maintenance ledger. The bridges, `spar-payload-scan`, and `review-brief`, which assembles the artifact both spar and the auditor take, live in the spar skill's `scripts/` under `~/.agents`, shared by every tool like the skill itself.
- Each bridge runs one read-only, offline, subscription-authenticated, single-turn reviewer from the caller's repository root. Unset `spar.consent` permits review; when set, only literal `true` passes, and empty values or lookup failures refuse. Flags are hard-coded: the reviewer reads the repository except Git internals and credential-shaped paths, has no write, web, MCP, plugin, subagent, or project-instruction surface, starts from a scrubbed environment, and runs under a hard timeout in its own process group. The Codex reviewer uses a read-only, network-off sandboxed shell; the Claude reviewer has only Read, Glob, and Grep. Reply-only stdout stays separate from stderr's validated reviewer ID and safe `model`/`effort`/`tier`/`clientversion` provenance. Unexposed or unsafe values are `unknown`, never inferred from configured preferences.
- Review-recommended paths: a staged change to `claude-code/.claude/settings.json`, `templates/codex/config.toml`, `opencode/.config/opencode/opencode.json`, a bridge, the scanner, `templates/hooks/commit-gate`, a skill script under `agents/.agents/skills/*/scripts`, the OpenCode plugin, or `agents/.agents/shared-guidance.md` is where a spar or auditor review before the packet earns its cost. No review is mandatory.
- `spar-payload-scan` bounds requests/artifacts, rejects credential-shaped values and sensitive paths (including copied stores), inlines artifacts, and rescans replies. Bridges pass `outbound --root REPO [--scratch-root PRIVATE_TMPDIR] -- FILE...`, keeping artifact operands out of options. Temporary artifacts require an explicitly selected private, owned caller `TMPDIR` below `/tmp` or `/var/tmp`, not a shared tool root; lexical and resolved paths are checked. This selects a private directory, not a new trust tier or proof of session identity. Reviewer runtimes may not resolve inside the repository or temp roots; reviewers receive no scratch-write grant. Addition-only `diff` mode is not complete publication coverage: governance also scans complete new objects and raw commit metadata.

## State and Deployment

- Stow runs with `--no-folding`, so every managed parent under `$HOME` is a real directory and only leaf files are links; generated host state therefore never reaches a package source. The one exception is `~/.agents/skills/<name>`: Stow skips the `agents` package's skills directory and `make stow` links each skill directory whole, because Codex's skill loader follows directory links and skips file links, and nothing writes inside a skill. `make clean` removes only dangling links whose text names a package entry this repository has or once had, and prunes the retired managed directories those links leave empty. `make stow` and `make restow` reconcile `~/.codex/config.toml`: the template owns root keys and its tables, host-only tables are preserved verbatim, the `hooks.state` trust records Codex writes after a session survive under the template's hooks table, the root `service_tier` a `/fast` choice writes survives as a host-owned key while the template leaves it out, unless the host root is still exactly the root of a template this repository once carried, per Git history, which the harness wrote and reconciles away; the rule is textual, so a root from an uncommitted template keeps the key until `/fast` is toggled off, and `make verify` attests that the host file carries the template's boundaries.
- Empty package directories are not tracked; a directory appears in a package only when it holds a managed file.
- Node.js is an EyrAgents verification prerequisite, not EyrWSL's baseline.
- A change that alters deployed state, such as the package layout, link targets, or the host Codex config, is deployed on the host where it is made, and the same commit adds a host pass item to `docs/maintenance.md` with the exact steps for the other host; the agent runs that item in the next session on that host, after H pulls, and removes it when done.
- The gates follow the `commit` skill's contract: `make lint` and `make check` are the repository checks, which CI also runs on every push to `main` and every pull request, and `make restow` and `make verify` are the host verification; `make restow` refuses when the managed links resolve into another clone. `make canary` runs each tool once, non-interactively, from a throwaway repository and asserts the skills inventory, the gate's denial with HEAD unchanged, a read under the clone, a read of a system file, a read of a fixture under `/tmp`, and a credential refusal: host verification with model calls that the agent runs itself after `make restow`, never a gate and never handed to H. Restart OpenCode after changing its config or skills. Record only unresolved failures or live revalidation needs in `docs/maintenance.md`.

## Skills

- `commit`: run the repository's gates, then stage, review, and commit one exact atomic change with H's approval.
- `publish`: review the exact commits a push, release, or pull request would expose, then verify the push and the published state after H runs it.
- `spar`: value-based cross-model review through a read-only reviewer bridge.
- `eyrsync`: this repository's own skill, under `.agents/skills` with a `.claude/skills` symlink, since Codex and OpenCode discover `.agents/skills` natively: sync the harness against the tools' official documentation, changelogs, and the Agent Skills specification, the way omasync syncs the sibling repositories against Omarchy, and the sibling repositories against the harness where they depend on it.
- `omarchy`: required for end-user Linux desktop, Hyprland, Omarchy, terminal, theme, and display configuration. Omarchy installs it and `diagnose-crash` as links under `~/.claude/skills` and `~/.agents/skills`; they resolve outside the packages, and `make clean` never touches them.
